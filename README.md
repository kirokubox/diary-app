# Yuki Diary App

自分専用のWeb日記アプリです。

日々の出来事・感情・思考を自由に書きながら、メタ認知、言語化、文章力を少しずつ育てるためのアプリです。Google Keepのように長文を自由に書ける体験を残しつつ、検索、整理、バックアップ、復元をしやすくしています。

現在はPWA対応済みです。Pixel 8などのAndroid Chromeで開き、ホーム画面に追加すると、普通のスマホアプリに近い感覚で起動できます。

## 開発環境での起動方法

初回だけ、依存パッケージをインストールします。

```bash
npm install
```

アプリを起動します。

```bash
npm run dev
```

起動すると、ターミナルに次のようなURLが表示されます。

```bash
http://localhost:5173/
```

このURLをPCのChromeなどで開くと、日記アプリを使えます。

## スマホから確認する方法

開発中のアプリをPixel 8などのスマホから確認する場合は、PCとスマホを同じWi-Fiに接続してください。

PC側で次のコマンドを実行します。

```bash
npm.cmd run dev -- --host 0.0.0.0
```

ターミナルに `Network` のURLが表示されます。

```bash
Network: http://192.168.1.10:5173/
```

この `Network` URLをPixel 8のChromeで開くと、スマホから開発中のアプリを確認できます。

注意: `http://192.168...` のようなLAN内URLは、スマホでの画面表示確認には使えます。ただし、Service Workerは原則としてHTTPSまたはlocalhostで有効になるため、LAN内HTTPではPWAのインストールやオフライン動作を完全には確認できない場合があります。PWAとして本格確認する場合は、HTTPSで配信するか、実際の運用URLで確認してください。

## ホーム画面に追加する方法

Pixel 8 / Android Chromeでの手順です。

1. Pixel 8のChromeでアプリURLを開く
2. 右上のメニューを開く
3. 「ホーム画面に追加」または「アプリをインストール」を選ぶ
4. ホーム画面に追加されたアイコンから起動できることを確認する

PWAとして起動すると、ブラウザのアドレスバーがない `standalone` 表示に近い形で開けます。

## PWA対応内容

- Web App Manifestを追加
- アプリ名を `Yuki Diary` に設定
- 短い名前を `Diary` に設定
- 表示モードを `standalone` に設定
- 起動URLを `/` に設定
- portrait向けに設定
- 192x192 / 512x512 の仮アイコンを追加
- Service Workerを追加
- 一度開いたあと、最低限オフラインでも画面を開けるようにアプリ本体をキャッシュ

日記データの保存先は、これまで通りブラウザ内のIndexedDBです。PWA化してもクラウド同期はされません。

## デプロイ候補

将来的な公開先の候補は以下です。

- Netlify
- Vercel
- GitHub Pages

どこにデプロイしても、日記本文がサーバー側に保存されるわけではありません。公開されるのはアプリ本体のHTML、CSS、JavaScript、manifest、アイコン、Service Workerです。

ただし、公開URLを知っている人はアプリ画面を開ける可能性があります。自分専用で使う場合は、公開URLをSNSやnoteに載せないでください。

アプリは検索エンジンにインデックスされる状態にしている（2026-07-29に検索避けを解除）。日記の本文自体は公開URLに保存されず、端末内のIndexedDBにあるため、URLを知っている人はアプリ画面を開けますが、他人の日記が見える心配はありません。

## 保存場所とプライバシー注意点

このアプリはサーバーを使いません。ログイン機能も外部データベースもありません。

日記データと写真は、使っているブラウザのIndexedDBに保存されます。つまり、基本的には「その端末の、そのブラウザの中」に保存されます。

保存されているストアは3つです（データベース名 `yuki-diary-app`、バージョン2）。

| ストア | 中身 |
| --- | --- |
| `entries` | 日記1日分（振り返り・日記・らくがきメモ・睡眠・写真のメタデータ） |
| `photos` | 写真の画像本体 |
| `settings` | テンプレート・生活日付設定 |

注意してください:

- 日記データも写真も、ブラウザ内保存であり、クラウド保存ではありません。
- スマホとPCでデータは自動同期されません。
- スマホで書いた日記はスマホ側のブラウザに保存されます。
- PCで書いた日記はPC側のブラウザに保存されます。
- Chromeの閲覧データやサイトデータを削除すると、日記データが消える可能性があります。
- 別のブラウザで開くと、同じ日記データは表示されません。
- シークレットウィンドウで使うと、データが残らない可能性があります。
- JSONバックアップと写真つきZIPバックアップをGitHubや公開フォルダに入れないでください。
- 公開URLを不用意に共有しないでください。

本番運用時は、スマホをメイン端末にするか、PCをメイン端末にするかを決めて使うのがおすすめです。複数端末で使う場合は、JSONエクスポートとJSONインポートで手動移行してください。

## 写真機能

2026-07-30に写真機能を追加しました。文字中心の日記を壊さず、その日の景色や変化も一緒に残すための機能です。写真がなくても、これまでどおり使えます。

- 1日最大6枚まで。端末の写真ライブラリから複数選択で追加できます（追加順に表示）
- 入力画面では**一番下**に「今日の写真」、閲覧モードでは**日記の下・らくがきメモ履歴の上**に表示します
- サムネイルは3列の正方形（表示上だけ中央トリミング）。タップで拡大表示（元の縦横比・左右スワイプ・位置表示）
- 削除は拡大表示の中からのみ。確認ダイアログを挟み、その1枚だけを消します
- 一覧では、写真がある日に `📷 3` のように枚数だけ表示します（一覧で画像は読み込みません）
- 写真ごとのタイトル・キャプション・タグ・分類・撮影場所・写真専用検索は、意図的に作っていません

保存の仕組み:

- 画像はIndexedDBの `photos` ストアに保存します（日記本体とは別置き。日記側は枚数などのメタデータだけを持ちます）
- 追加時に**長辺1600pxへ縮小し、WebP（品質0.8）で再エンコード**します。EXIF（撮影場所などのメタデータ）は残りません
- 元の写真は端末のギャラリー側にそのまま残ります
- 1枚あたり約150〜300KB。設定画面の「写真の保存容量」で保存枚数・合計サイズ・ブラウザの上限を確認できます
- 写真の保存に失敗しても、日記の文字データは失われません（写真1枚ごとに独立して処理します）

## バックアップ方法

日記データはブラウザ内に保存されます。大事な日記を失わないため、定期的にJSONバックアップを取ってください。

手順:

1. アプリを開く
2. 下部タブの「設定」を開く
3. 「JSONエクスポート」を押す
4. `diary-backup-YYYY-MM-DD.json` のようなファイルが保存される
5. そのJSONファイルをOneDrive、外付けストレージ、別フォルダなどに保管する

JSONファイルは復元用です。日記データ、テンプレート、タグ候補が含まれます。

本番運用する場合は、週1回以上のJSONバックアップを推奨します。日記をたくさん書く時期は、もっと短い間隔でバックアップしてもよいです。

### 写真つきZIPバックアップ

**JSONエクスポートに写真の画像は入りません。** 入るのは「その日に写真が何枚あるか」という情報だけです。写真も残す場合は、設定画面の「写真つきZIPエクスポート」を使ってください。

1. 下部タブの「設定」を開く
2. 「写真つきZIPエクスポート」を押す
3. `diary-photo-backup-YYYY-MM-DD.zip` が保存される
4. JSONバックアップと同じ保管先へコピーする

ZIPの中身:

```text
diary-photo-backup-2026-07-30.zip
├─ diary-backup.json            通常のJSONバックアップと同じ形式
├─ photos/2026-07-30/01_写真ID.webp
├─ photos.json                  画像ファイルと日記の対応表
└─ README.txt                   中身の説明と注意
```

ZIP1つで日記も写真も戻せるので、機種変更のときはZIPだけ持っていけば足ります。展開すればPCで普通に写真として見られます。

**ZIPには本物の写真が入ります。JSONバックアップと同じ扱いで、GitHubや公開フォルダには置かないでください。**

## 復元方法

JSONバックアップから復元する場合は、設定画面の「JSONインポート」を使います。

手順:

1. アプリを開く
2. 下部タブの「設定」を開く
3. 「JSONインポート」でバックアップJSONを選ぶ
4. プレビューで新規追加・重複・エラー・警告の件数を確認する
5. 問題なければ「新規データだけ追加する」を押す

インポートは**既存の日記を上書きしません**。同じ日付の日記がある日はスキップします（日付をIDとして扱います）。

写真も戻す場合は「写真つきZIPインポート」を使います。動きは同じで、本文を追加したあと、**日記から参照されていてまだ端末に無い画像だけ**を復元します（既にある画像は上書きしません）。そのため「本文は残っているが写真だけ消えた」状態でも、写真だけを戻せます。

JSONだけで復元すると、日記の文字は戻りますが写真は「読み込めません」と表示されます。この状態はあとから写真つきZIPを読み込めば直ります（枚数の情報は残しているため）。

## JSONとMarkdownの使い分け

JSON:

- 復元用
- バックアップ用
- 日記データを安全に戻したいときに使う

Markdown:

- 読み返し用
- 共有用
- ChatGPTに貼る用
- 文章として保管したいときに使う

Markdownは見やすい文章形式ですが、復元用ではありません。復元したい場合は、必ずJSONエクスポートを使ってください。

## 基本機能

- 今日の日記を書く
- 日付を変えて過去日記・未来日記を書く
- 起床時間、睡眠時間、仮眠時間、本文を記録する
- 入力後、約1秒で自動保存する
- 保存ボタンで手動保存する
- 一覧で最近の眠りグラフ（タップで推定就寝などの詳細）、直近の日記、1か月前・1年前・同じ季節の日記を見る
- 一覧・検索から開いた過去日記は、入力欄なしの閲覧モードで読む（「編集する」で入力モードへ）
- キーワードと期間で検索する（一致箇所をハイライト表示）
- その日の写真を最大6枚残す（3列サムネイル・拡大表示・削除）
- その日の日記をMarkdownでエクスポートする
- 全日記をJSONでバックアップする（写真の画像は含まない）
- 全日記と写真を写真つきZIPでバックアップする
- 全日記をMarkdownで出力する
- JSONバックアップ／写真つきZIPから復元する
- テンプレートを編集する
- 日記や全データを確認つきで削除する
